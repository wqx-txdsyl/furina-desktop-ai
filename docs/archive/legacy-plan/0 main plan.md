\# 芙宁娜 AI Desktop Companion



\## 产品定义



\### 一句话定义



> \*\*一个真正生活在用户电脑桌面中的 AI 芙宁娜：她拥有身体、情绪、需求、记忆、行动意图和电脑操作能力，而不是一个等待用户点击的动画桌宠。\*\*



核心体验不是：



> “我点击她，她做一个动作。”

\# 一、产品的三个核心原则



\## 原则 1：AI 是“人”，素材是“身体”



这是整个项目最重要的架构原则。

> LLM → 播放某个 GIF

> LLM → 判断“我现在想做什么” → 行为系统规划 → 动作系统执行 → 素材负责表现

不是：




```text

↓

她产生“想提醒主人休息”的意图

↓

决定靠近用户

↓

走过去

↓

观察用户

↓

决定是否说话

↓

说：

“你已经坐这么久了吧？”

```



\*\*行为产生于状态，而不是状态产生于动画。\*\*

\# 三十六、我建议我们现在先不要写代码



在正式 PRD 之前，应该把下面这 \*\*7 个东西彻底定死\*\*：



\### ① 角色状态树



到底有哪些状态、状态如何转移。



\### ② 素材规范



到底要生成多少素材、每种素材怎么命名、怎么标注、怎么保持角色一致性。



\### ③ 行为系统



她什么时候自己走、什么时候说话、什么时候吃饭、什么时候玩、什么时候工作。



\### ④ 互动系统



摸头、拖拽、点击、喂食、玩耍、靠近、窗口互动全部怎么判定。



\### ⑤ Agent 系统



她究竟能操作电脑到什么程度，以及权限怎么控制。



\### ⑥ 记忆系统



什么值得记，什么时候记，记忆如何影响人格和行为。



\### ⑦ UI / Runtime



Windows 桌面窗口、透明窗口、置顶、穿透、点击区域、窗口检测、渲染、FPS、素材缓存等怎么实现。



\---



\*\*尤其是第 ①～③，我认为现在最值得继续往下打磨。\*\*



因为你的真正难点已经不是“怎么让芙宁娜动起来”，而是：



> \*\*如何让一个只有大量 PNG / 多帧动画的角色，在没有 Live2D 的情况下，仍然表现出“她自己决定下一步要干什么”的感觉。\*\*



只要这个行为系统设计得足够好，视觉素材哪怕只是二维图片，最终体验也可以非常接近你最开始说的：



> \*\*“像电脑里真的住着一个人。”\*\*
